Reporting and Analytics

A step-by-step script for BRD Section 11. You are checking that a report or dashboard widget can be built on any object, that a report can follow one relationship to a related record, and that charts use the same five functions as Roll-Up Summary fields. It uses the Policy and Insured Life objects already in the system, and you delete what you create at the end.

Reports on any object

BRD §11.1 — the report builder works on any object you may read, standard or custom, and is not limited to the pre-defined Sales dashboards.

  1. Click Reports in the left menu, then New Report. Set Object to Insured Life (the list offers every object you may read: Broker, Claim, Insured Life, Policy, S9 Case).
  2. Set Group By to Relationship. Under AGGREGATIONS choose Sum and the field Sum Assured. Under CHART TYPE click Table, then click Run (top right).
  3. Compare with the data: open the Insured Lives list and add up Sum Assured by relationship (six lives: two Main Members, two Spouses, two Children).
ExpectedThe table has two columns, Relationship and Sum of Sum Assured: Main Member 350,000, Spouse 230,000, Child 70,000. The totals equal what you add up from the list.
  1. Staying on the same report, change the function (the first list under AGGREGATIONS) to Count and click Run. Then Average, Min and Max, each time choosing the field Sum Assured and clicking Run.
ExpectedCount: 2 in each group. Average: Main Member 175,000, Spouse 115,000, Child 35,000. Min: 100,000 / 80,000 / 20,000. Max: 250,000 / 150,000 / 50,000. Each average is the group total from Test 1 divided by 2.
  1. Click Reports in the left menu, then New Report. Set Object to Policy, Group By to Policy Number, choose Table, then Sum of Total Sum Assured and click Run.
  2. Open the policies in the Policies list and read each one's Total Sum Assured.
ExpectedPOL-TEST-001 450,000, POL-CL-001 200,000, POL-FP-001 0: the same figures the Roll-Up Summary field shows on each policy. The aggregate dropdown for numbers lists the Roll-Up fields (Total Insured Lives, Total Sum Assured, Spouse Cover Total) next to Claims Lodged, Commission Rate and Monthly Premium.
  1. Click Reports in the left menu, then New Report. Set Object to Insured Life, Table, leave Group By on None (raw records) and the function on Count.
  2. Click Add Filter. Choose the field Sum Assured, the operator >, type 100000 in Value and click Run.
ExpectedFirst run: a single Count of 2 (two lives are insured for more than 100,000). The operator list offers =, ≠, >, ≥, <, ≤, contains, not contains, starts with, in, is empty, is not empty and between.
  1. Build the report in Test 6 (below), type S11 Sum Assured by Policy in Name, and click Save. You land on the saved report.
  2. Click Reports in the left menu, open S11 Sum Assured by Policy, then click Refresh.
ExpectedThe saved report shows the same chart with the same figures every time (it is re-run on the live data, not stored as a picture). Edit opens it back in the builder with every choice still set. Needs a person: look at the bar chart itself; the checking tool read the labels and values but cannot judge the picture.

Reports across a relationship (one level)

BRD §11.2 — a report can follow one Lookup or Master-Detail relationship to the related object's fields.

  1. Click Reports in the left menu, then New Report. Set Object to Insured Life, Sum of Sum Assured, and leave Group By on None (raw records).
  2. Under CROSS-OBJECT set Lookup Field to Policy → policy. A new list Group by (related) appears; choose Policy Number. Choose Bar and click Run.
ExpectedTwo bars: POL-TEST-001 (450,000) and POL-CL-001 (200,000). The axis is titled Policy: Policy Number, so you can tell the group comes from the parent record. The figures equal the sum of each policy’s own lives in the Insured Lives list. POL-FP-001 has no lives, so it does not appear.
  1. Change Group by (related) to Policy Status, choose Table and click Run.
ExpectedOne row: Active — 650,000. All lives belong to Active policies and the total is the sum of every life (350,000 + 230,000 + 70,000).
  1. Look at Group by (related): it lists only the fields of the Policy itself (for example Policy Number, Policy Status, Type), never fields of records Policy points to.
  2. Needs a person / not clicked: there is no screen that lets you type a path such as policy.broker.name; it can only be sent to the server directly.
ExpectedNo second hop can be chosen on screen. Sent directly, the server refuses a path through a second relationship, a field that is not a relationship, and a relationship that does not point at the named object, each with a plain message (proven by the automated suite, 91 checks). A Lookup field is handled by exactly the same code as the Master-Detail used here; the suite builds one (Task → Project) and reports across it, because this system's sample objects hold no Lookup between two reportable objects.

One calculation model

BRD §11.3 — charts and reports use the same five functions as Roll-Up Summary fields.

  1. In Reports → New Report open the function list under AGGREGATIONS.
  2. Open Dashboards, any dashboard, click Edit, then Add Widget or the Configure button on a widget, and open Value function.
  3. Go to Setup → Object Settings, open an object, Fields → Add Field, choose type Roll-Up Summary and look at its function list (this last list was read from the form's code, not clicked; it was proven by the Section 3 manual).
ExpectedAll three offer the same five functions: Count, Sum, Average, Min, Max (Roll-Up shows them with a short description, e.g. “Average — mean value”). Nothing is missing and nothing extra is offered. Anything else (for example “median”) sent directly to the server is refused with “Unsupported function”.

Which objects, which people

Reports follow the object setting Allow Reports and each person's rights.

  1. Open Setup → Object Settings → S9 Case → Edit, untick Allow Reports (“Include in Analytics and report building”) and save.
  2. In Reports → New Report choose the object S9 Case and click Run.
  3. Open Analytics in the left menu and, under Quick Report, choose S9 Case.
  4. Tick Allow Reports again on S9 Case and save.
ExpectedBoth places say Reporting is turned off for S9 Case. and show no data. Quick Report on Policy still draws its chart. After step 4 S9 Case reports again. (Steps 1 and 4 were done through the screen's underlying request in the check: the switch itself was not clicked.)
  1. Open Dashboards and click New Dashboard. Type S11 Insured Lives in Name and click Save, then Add Widget three times.
  2. Configure each: (a) type Metric, title Total sum assured, CRM Object Insured Life, Value function Sum, Numeric field Sum Assured; (b) the same with function Max, title Max sum assured; (c) type Bar Chart, title Average by relationship, Group by field Relationship, function Average, field Sum Assured. Click Save Widget each time, then Save and Preview.
ExpectedTotal sum assured 650,000, Max sum assured 250,000, and a bar chart with Main Member (175,000), Spouse (115,000), Child (35,000). The CRM Object list offers Broker, Claim, Insured Life, Policy and S9 Case wherever you are in the system. (The dashboard was created through the screen's underlying request and its three widgets were opened and read; the New Dashboard dialog was opened but not saved.) Dashboard widgets group by a field of their own object; to go across a relationship use a report (Tests 6–7).
  1. Needs a person: sign in as a second, non-administrator user (the pane can only hold one session). Their Role or Permission Set needs View Analytics to open and run reports, and Manage Analytics to save, change or delete one.
  2. Run the automated suite instead: node tests/section11-reporting.e2e.mjs from the backend folder.
ExpectedThe suite proves, with real non-administrator users: no View Analytics → the report list and running a report are refused; View Analytics → reports run (including across a relationship) but cannot be saved or deleted; Manage Analytics → can save and delete; a user who may see no records gets 0 in a report and in a dashboard widget; a field the user may not see cannot be grouped on, filtered on, totalled, or appear in raw rows; an object with Allow Reports off is refused in reports and widgets. Section 9 separately proved that Read on an object (not the App) is what lets someone report on it.
  1. Open Reports, open S11 Sum Assured by Policy and delete it (the Delete control on the report). Open Dashboards and delete S11 Insured Lives.
  2. Confirm Allow Reports is ticked on S9 Case.
ExpectedNo report or dashboard created by this manual remains and no object setting is changed. (The delete confirmations use a browser pop-up that the checking tool cannot press; deletion was done through the request the screen sends.)
