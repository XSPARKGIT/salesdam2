Data Import and Export

A step-by-step script for BRD Section 12. You are checking that the import screen offers every field of an object (including ones created today) as a mapping target, that you can choose exactly which fields to export, and that only an administrator can switch off validation rules and flows for a bulk import. You build a small throwaway object and delete it at the end.

What you need

  • A throwaway object. Create S12 Lead (Setup → Object Settings → New Object) with the record name set to Auto Number, label Lead Ref, prefix LD-. Then add these fields (Fields tab → New Field): Company (Text, required), Score (Number), Stage (Picklist: New, Qualified, Lost), Start Date (Date), Policy (Lookup to Policy), Internal Notes (Text) and Double Score (Formula, Number, score * 2).
  • One validation rule on S12 Lead: expression score < 0, error message Score cannot be negative., error field Score, active.
  • One flow (Automation → New Flow, record-triggered on S12 Lead, when a record is created) with one Update Record step that sets Description to Flow stamped this lead. Save and activate it.
  • A CSV file. Test 2 gives the text of s12-leads.csv; save it on your computer.

The same setup is removed at the end (Test 12). Your Salesdam contact can supply the object, rule and flow ready-made if you prefer.

Mapping columns to fields

BRD §12.1 — the column-to-field step reads the object's live field list, so a new custom field is a mapping target straight away, with no development work.

  1. Open Setup → Admin Settings → Data Import. In Target Object choose S12 Lead (Custom). Under the object, read the line Available fields.
  2. In another tab, open Setup → Object Settings → S12 Lead → Fields → New Field. Create a Text field called Region and save. (The click path for creating a field is the one proved in the Metadata Engine manual.)
  3. Return to the Data Import tab and click ↻ Refresh fields. (The page also refreshes by itself when you switch back to the tab.)
ExpectedBefore: Available fields lists ten fields and does not include region. After the refresh the line reads (11 fields loaded) and includes region. No code change or restart was needed.
  1. Make a file s12-leads.csv (a spreadsheet saved as CSV is fine) with these seven lines, the first being the headers:
    Company,Score,stage,start date,Region,Double Score,Comments
    Acme Ltd,10,Qualified,2026-03-15,North,99,hello
    Beta Ltd,-4,New,2026-03-16,South,1,rule row
    ,5,New,2026-03-17,East,2,missing company
    Gamma Ltd,abc,Gone,notadate,West,3,bad types
    Delta Ltd,8,Lost,15/03/2026,West,4,date style
    Epsilon Ltd,9,qualified,2026-03-18,West,5,case
  2. On Data Import click the drop area (Click or drag a file here) and choose the file. Needs a person: an automated run cannot operate the file chooser, so the file was dropped onto the same area instead.
  3. Read the table CSV COLUMN / SAMPLE VALUE / MAPS TO FIELD. Open the list on the Double Score row.
ExpectedCompany, Score, stage, start date and Region are matched to Company, Score, Stage, Start Date and Region automatically (capitals and spaces do not matter, and the newly created Region is picked up too). Double Score and Comments show — Skip this column —. The lists offer every field except the calculated ones (Lead Ref and Double Score are not offered), because the system fills those in. The summary reads 7 columns, 5 mapped, 2 skipped.
  1. Click Cancel, then choose a file whose only headers are Score and Stage (one row: 1,New).
  2. Read the notice above the table, and click Cancel again.
ExpectedThe notice reads Required field Company has no column. Every row will be rejected unless you add that column to the file or map an existing column to it. Nothing has been imported.
  1. Choose s12-leads.csv again (the file from Test 2). Click Review & Import. Leave Bypass Validation Rules and Flows unticked. Click Confirm Import.
  2. Read the result screen.
ExpectedResult: 1 Created, 5 Failed, and a Why rows failed list, one line per refused row, all of a row's problems together: Row 3 Score cannot be negative. · Row 4 "Company" is required. · Row 5 "Score" must be a number, "Stage" has invalid value "Gone", "Start Date" must be a valid date. · Row 6 "Start Date" must be a valid date (dates must be written 2026-03-15; 15/03/2026 is refused). · Row 7 "Stage" has invalid value "qualified" (picklist values must match exactly). The page title is Import Complete; Updated shows a dash because an import only creates records.

Choosing what to export

BRD §12.2 — export any selection of fields per object, in the format and with the filters you choose, never beyond what the exporting person may see.

  1. Open Setup → Admin Settings → Data Export. Choose S12 Lead as Object to Export. Note the count 11 of 11 fields selected and that the format is CSV.
  2. Click Deselect all, then tick Score, Company and Double Score. The button now reads Export S12 Lead as CSV · 3 fields. Click it.
  3. Open the downloaded s12_lead-export.csv.
ExpectedA message says Exported 3 fields from s12_lead as CSV. The file has exactly three columns, Score, Company, Double Score, and one row for the lead the Test 4 import created, plus the leads from earlier tests: 10,Acme Ltd,20 (Double Score is the real value 10 × 2, not empty). Columns follow the order of the fields on the object, not the order you ticked them.
  1. Still on Data Export with the same three fields, set the filter row to Score, > greater than, value 9. The header says 1 active filter.
  2. Click the export button and open the file.
ExpectedOnly rows whose Score is above 9 are in the file (in the example data 10,Acme Ltd,20 and, if Test 10 has been run, 20,Bypass Ok Ltd,40). Records with a lower score are absent.
  1. Click JSON, leave every field ticked (Select all if needed) and click the export button. Open the file.
ExpectedThe file is a list of records, each carrying all of the object's fields (name, owner_id, description, score, stage, start_date, policy_ref, company, internal_notes, double_score, region). Roll-Up Summary fields are not offered on this screen.
  1. In Setup → Roles, create a role S12 Importer that may read, create, import and export S12 Lead, with Import Data and Export Data ticked under System Permissions, and with Internal Notes not visible (Field-Level Security). Create a user with that role.
  2. Sign in as that user, open Data Export, choose S12 Lead, and look for Internal Notes in the field list. Then try to request it anyway: …/admin/export?object=s12_lead&fields=company,score,internal_notes.
ExpectedInternal Notes is not offered. The forced request returns the file with only Score and Company: the hidden column is silently dropped, not an error. Needs a person: the pane can only be signed in as one person, so this was proved by signing in as that user through the same requests the screen sends (admin export and per-object export, requested fields and all fields) rather than by clicking.

Bypassing validation rules and flows

BRD §12.3 — a bulk import may skip Validation Rules and Flows only when an administrator explicitly asks for it. The default is the full pipeline.

  1. Open Data Export for S12 Lead, deselect everything and tick only Company and Description. Export and open the file.
ExpectedThe lead imported in Test 4 (Acme Ltd) has Flow stamped this lead in Description: the flow ran for the imported record.
  1. On Data Import choose S12 Lead and a file with the headers Company, Score, Stage, Start Date and three rows: Bypass Neg Ltd,-9,New,2026-05-01 · Bypass Ok Ltd,20,Qualified,2026-05-02 · Bypass Bad Ltd,abc,Gone,notadate.
  2. Click Review & Import. The tick box Bypass Validation Rules and Flows (admin only; for data migration) is visible and unticked. Tick it: a warning appears, Warning: validation rules and flows will be skipped for this import only. Click Confirm Import and accept the confirmation pop-up (Bypass Validation Rules and Flows for this import? …). Needs a person for the pop-up: the checking tool cannot press it, so it was accepted by overriding the browser confirm.
  3. Read the result, then repeat the Test 9 export (Company, Description). Open Admin → Audit Logs (Setup) and read the newest import rows for S12 Lead.
ExpectedResult: 2 Created, 1 Failed. The negative-score row was created (the validation rule was skipped), and the row with a bad number, picklist value and date is still refused: bypass skips rules and flows only, never the data-type checks. In the export, Bypass Neg Ltd and Bypass Ok Ltd have an empty Description: the flow did not run. Audit Logs has a new import row with the new Details column reading created: 2, failed: 1, bypassValidation: true; the Test 4 row reads bypassValidation: false. Duplicate rules still apply to a bypassed import.
  1. Signed in as the S12 Importer user from Test 8, open Data Import, choose S12 Lead, upload a file and click Review & Import.
  2. Send an import with the bypass flag set anyway (bypassValidation=true) to /admin/import and to /records/s12_lead/import.
ExpectedThe bypass tick box is not on the screen for this user. A normal import by this user creates the valid row and refuses the negative one (Score cannot be negative.), so rules apply to them. Both forged requests are refused with 403 — Automation bypass is restricted to administrators. A file that maps a column onto Internal Notes (hidden) is refused with 403 — You are not authorized to import into field "internal_notes". Needs a person for the screen itself (one person can be signed in in the pane); the refusals were proved through the requests the screen sends.

Clean up

  1. Setup → Object Settings → S12 Lead → delete the object (type its name when asked); its records go with it. Delete the flow S12 Lead Stamp in Automation. Deactivate the test user and delete the S12 Importer role.
ExpectedNo S12 object, flow, role or active test user remains. Audit Logs keep the import and export rows by design.

Not covered by clicking

Proven another way, or not proven here

  • Choosing the file with the file chooser, and the bypass confirmation pop-up, cannot be operated by the checking tool (Tests 2, 3, 4 and 10). The same screen code ran with the file dropped on the drop area.
  • Anything that needs a second signed-in person (Tests 8 and 11) was proved through requests as a real test user, not on screen.
  • Duplicate rules running on import, and an exported file importing back unchanged, are proved by the automated suites duplicate-detection (21/21) and csv-roundtrip (11/11), not clicked here. The suite section12-import-export (15/15) also proves that a bypassed import skips the flow.
  • Dates must be written 2026-03-15 and picklist values must match exactly; other date styles are refused with a clear message, not converted. Columns in an export follow the object\'s field order, not your tick order. The Import screen only reads .csv, .xlsx and .xls files and stops at 5,000 rows.
  • A person without administrator rights cannot create records on an object whose name field is plain Text (the name is read-only to them), so they cannot import into it either. Use an Auto Number name, as S12 Lead does.
