Search and Views

A step-by-step script for BRD Section 10. You are checking that anything marked Searchable is found by Global Search without further work, that list views are data on the object rather than code, and that a brand-new object gets Kanban and Calendar just by choosing driver fields. You will create one throwaway object and remove it at the end.

Global Search (automatic indexing)

BRD §10.1 — any object or field marked Searchable is included in Global Search without further engineering.

  1. Go to Setup → Object Settings and click New Object. Set Object Label S10 Gadget and Plural Label S10 Gadgets, leave Allow Search switched on, and click Create Object.
  2. On the Fields tab click Add Field and add: Serial (Text), Notes (Text; untick Searchable — include in Global Search), Stage (Picklist; type New and click Add, then Live and Add) and Due (Date). Click Save Field each time. Serial and Due keep Searchable ticked.
  3. Go to Workspaces → Insurance → Objects tab, click S10 Gadget so it is selected (the count reads 4 objects selected) and click Save Changes. (A new object is invisible until it is in a workspace.)
  4. Open the S10 Gadgets list and click New S10 Gadget three times (Create Record each time): Zephyrine One (Serial QX7741, Notes bluefalcon, Stage New, Due 1 Dec 2026), Zephyrine Two (QX8852, redkestrel, Live, 5 Dec 2026) and Quillon Three (QX9963, greenheron, New, 9 Dec 2026).
  5. Type Zephyrine in the search box at the top of the page (Search records, users…).
ExpectedThe drop-down lists Zephyrine Two and Zephyrine One, each tagged S10 Gadget. Quillon Three is not listed. Nobody had to switch on search for this object or write code for it.
  1. Type QX7741 in the search box.
ExpectedOnly Zephyrine One is listed: Serial is Searchable, so its value is part of the search text.
  1. Type bluefalcon, then redkestrel.
ExpectedNothing from S10 Gadget is listed. Notes is not Searchable, so its content is never indexed, although it shows on the record.
  1. Go to Setup → Object Settings, open S10 Gadget (Edit) and the Fields tab. On the Notes row click the pencil (Edit field), tick Searchable — include in Global Search and click Save Field.
  2. Wait a few seconds (the search index is rebuilt in the background; the database is remote). Search bluefalcon.
ExpectedZephyrine One is listed. Records that already existed were re-indexed automatically. If nothing appears yet, wait a few more seconds and search again.
  1. Edit the Notes field again, untick Searchable — include in Global Search and click Save Field. Wait a few seconds (the search index is rebuilt in the background; the database is remote). Search bluefalcon.
  2. Edit Serial, untick Searchable, save, wait, and search QX8852. Then tick Searchable on Serial again, save, wait, and search QX8852 once more.
ExpectedThe first two searches list nothing; the last lists Zephyrine Two. Turning a field off removes its old content from search without re-saving each record, and turning it on brings it back.
  1. On the Fields tab click Add Field and add a Text field Tag (Searchable stays ticked). Open Quillon Three, click Edit, type obsidian in Tag and click Save Changes.
  2. Wait a few seconds and search obsidian.
  3. Needs a person: delete the Tag field (pencil row → trash icon Delete field). The browser asks Delete field "Tag"?, which the automated pane cannot answer. Then search obsidian again.
ExpectedBefore the delete, Quillon Three is listed. After the delete it is not.
  1. Edit Zephyrine One, rename it Zephyrine Renamed and click Save Changes. Search Renamed, then One.
  2. Open Quillon Three, click Delete and confirm with Delete in the box that opens (it says the record is permanently deleted, but it goes to the Recycle Bin). Search Quillon.
  3. In the S10 Gadgets list click Recycle Bin, click Restore beside Quillon Three (no confirmation), and search Quillon again.
ExpectedThe new name is found and the old one is not. The deleted gadget disappears from the list and comes back when restored.
  1. In Setup → Object Settings → S10 Gadget → Object Details switch Allow Search off and click Save Changes. Search Zephyrine.
  2. Switch Allow Search on again, save, wait a few seconds and search Zephyrine.
ExpectedWith the setting off nothing from S10 Gadget is listed although the records still exist. With it on, they return.
  1. Go to Workspaces → Insurance → Objects, click S10 Gadget to deselect it (3 objects selected) and click Save Changes. Search Zephyrine.
  2. Select S10 Gadget again, save, and search Renamed.
ExpectedWhile the object is outside the App nothing from it is listed; once it is back, results return. Field-level hiding and sharing in search were proven in the Permissions and Sharing manual (Section 9); this test only shows the App boundary.

List views as metadata

BRD §10.2 — filters, columns, sort and the actions offered are defined as data on the object.

  1. Open the S10 Gadgets list. Click Choose columns, click Clear all, then click Name, Stage and Due in the Available list and click Apply.
  2. Click the Due column heading twice (once sorts oldest first, twice newest first).
  3. Click the view name (All S10 Gadgets) and choose New List View…. The box says it saves the 3 columns shown, sorted by due (descending). Name it New gadgets, add the condition Stage equals New and click Save View. (More on views: Section 4, Tests 18–25.)
ExpectedThe list shows Quillon Three then Zephyrine Renamed; Stage Live is excluded; only Name, Stage and Due show. The view appears under My Views and lives with the object, not in code for it.
  1. Look at the buttons above the S10 Gadgets list.
ExpectedMerge, Delete, Export, Import, Refresh, Recycle Bin and New S10 Gadget are present on this brand-new object. They come from the person’s permissions, not from anything built for this object.
Good to knowMerge, Delete, Export and Import are the same on every object. A few screens still add object-specific buttons: Tasks have Recurring Task and a Calendar shortcut, Quotes and Invoices have no plain New button, and Policies send New to the application flow. Buttons you add yourself (Section 4.4) are defined per object; a platform action such as Clone is always placed on the record, not on the list. Search finds whole words: Zephyrine is found, Zephy is not. Kanban cards show the Record Owner as an internal id, a known cosmetic gap.

Kanban and Calendar on a second object

BRD §10.3 — shown on a freshly created object; the full Kanban and Calendar checks are in the Page Layout manual, Section 4.

  1. In Setup → Object Settings → S10 Gadget → Object Details switch on Kanban View and choose Stage under Group By Field. Switch on Calendar View, choose Due under Date Field and Name under Title Field. Click Save Changes.
  2. Open the S10 Gadgets list and click the Kanban view icon, then the Calendar view icon.
ExpectedKanban shows a New column (2 cards: Quillon Three, Zephyrine Renamed) and a Live column (Zephyrine Two). The calendar for December 2026 shows Zephyrine Renamed on the 1st, Zephyrine Two on the 5th and Quillon Three on the 9th. No code was written for this object. Dragging a card between columns is covered in Section 4, Test 21 (Needs a person).
  1. In the same screen open the Group By Field and Date Field lists.
ExpectedGroup By Field offers only Stage (the only picklist) and Date Field offers only Due (the only date): Serial, Notes and Name cannot be chosen. A wrong choice sent directly to the server is refused with a message (proven by the automated suite).
  1. Under Workspaces → Insurance → Objects deselect S10 Gadget and click Save Changes.
  2. Open Setup → Object Settings → S10 Gadget, click Delete Object, type s10_gadget in the box and click Delete permanently.
ExpectedS10 Gadget disappears from Object Settings and from search, and its records, fields and saved view go with it. The Insurance App again lists Policies, Insured Lives and Claims.
Not covered by clickingRecords created by flows, custom code or conversions are indexed by the same rule, but this was proven by a check on the data layer, not on screen. Search results hiding fields a person may not see (Section 9) and dragging a Kanban card need a person.
