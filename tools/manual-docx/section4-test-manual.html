What has already been set up for you

  • Policy has two layouts: Policy - Admin (full) (the object default — three sections, the Information section in three columns) and Policy - Agent (simple) (one section, six fields).
  • Type on Policy offers Funeral Plan, Life Cover and Credit Life.
  • POL-00001 — Active, no Type, three insured lives (Thabo, Naledi and Lesedi Mokoena).
  • POL-00003 — Active, Type Credit Life, three insured lives (Sipho, Zanele and Anele Dlamini).
  • POL-00004 — Active, Type Funeral Plan, start date 1 November 2026.
  • Layout Assignment is set for Policy: Administrator uses the Admin layout; Standard User and Read Only use the Agent layout; Super User follows two rules (Type = Funeral Plan → Admin, then Type is set → Agent).
  • Kanban is on, driven by Policy Status. Calendar is on, driven by Start Date.
  • A saved list view Funeral Plans, and an action button Clone Policy that shows only on Active policies.

Two things worth knowing before you begin

  • Pages take a while to open. This environment runs the application on your machine but keeps its database in the cloud, so every screen waits on a number of round trips. Ten to thirty seconds for a setup or record page is normal here and is not a fault in the feature you are testing.
  • Layout changes in Part 1 are left unsaved on purpose. Where a test says don't save, reload the page afterwards — that throws the change away and leaves the example layouts exactly as they were for the next person.

Part 1 — Building a layout

BRD §4.1. Setup → Object Settings → Policy → Layout tab opens the layout builder, which every test in this part starts from.

  1. Go to Setup → Object Settings → Policy and open the Layout tab.
  2. Open the Layout picker at the top of the page and look at what it offers.
  3. Choose Policy - Agent (simple), look at the page, then switch back to Policy - Admin (full).
Expected Two layouts are listed — Policy - Admin (full) marked (object default) and Policy - Agent (simple). Admin has three sections (System Information, Information, Additional Information). Agent has one section, Policy, with six fields: Policy Number, Type, Start Date, Policy Status, Monthly Premium and Commission Rate.
  1. On Policy - Admin (full), find the Information section. Its column button reads 3 col.
  2. Click the button. Then click it again, and once more, watching the number and the field boxes each time.
Expected The button cycles 3 → 1 → 2 → 3 columns and the fields are redistributed across the columns each time. No field disappears — the same fields are there whichever column count you choose.
Don't save Reload the page when you have finished so the section goes back to three columns.
  1. At the bottom of the builder click Add Section.
  2. Click the new section's title and type Test Section.
  3. Reload the page without saving.
Expected A new section appears with two empty columns marked Drop fields here, and its title is editable. After the reload it is gone.
  1. On Policy - Admin (full), find Policy Number in the Information section.
  2. Hold the grip (the six dots) at the left of the field and drag it into a different column. Release.
  3. Drag it back to where it was, or reload the page without saving.
Expected The field lifts, a gap shows where it will land, and it stays in the new column when you let go. The other fields close up around the gap. The same works between sections.
Needs a person This is the one test that needs a real mouse. Dragging cannot be carried out by an automated script in this environment, so it has been left for you.
  1. On Policy - Admin (full), find Broker Email. Hover the highlighted * button at its right: Required on this layout.

  1. Open Policy - Agent (simple) in the builder.

  1. In the builder, on Policy - Admin (full), scroll below the sections to Related Lists.

Part 4 — Buttons on a record

BRD §4.4. Buttons are configuration, not code.

  1. Open POL-00001 and click Clone Policy in the header.
  2. Look at the form that opens, then click Cancel.
Expected A New Policy form opens with the details of POL-00001 already filled in. Nothing is saved until you click Create Record, so cancelling leaves no copy behind.
  1. Go to Setup → Object Settings → Policy → Action Buttons.
  2. Read the row for Clone Policy. Click New Button and look at the Action type choices, then close it.
Expected The row reads Runs: Platform action: Clone record · Shown when: Policy Status equals Active · Location: Record Detail. The choices for a button are: Flow (runs straight away), Screen flow (asks the user for input first) or Platform action (for example convert or clone).
  1. Open POL-00004 and note the Clone Policy button.
  2. Click Edit, set Policy Status to Lapsed, and save.
  3. Look at the header again. Then edit the policy, set Policy Status back to Active, and save.
Expected With Active the button is shown. Once the policy is Lapsed the button is gone. When it is Active again the button is back. The page needs no code change — only the condition on the button.

Still to be covered

These points sit outside this script:

  • Layouts as the other profiles. Only a Super User account exists here, so the Administrator, Standard User and Read Only defaults are checked by their settings, not by signing in as each.
  • Filters on many-to-many related lists. Sort, columns and buttons apply; default filters do not.
  • Layout-only Required and Read-only rules are enforced on screen, not by the API or by Data Import.

Reporting a problem

For anything that does not match the expected result, note the test number, what you saw instead, and the record or layout you were working on. A screenshot of the screen as it looked when it went wrong is usually enough for us to reproduce it.
